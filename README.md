# 결함 위치 도면 마킹 도구 + 번호 스탬프 카메라 연동

[결함 위치 도면 마킹 도구](https://github.com/yeop9701/defect-location-marker)(2026-10-19, `c26b54c`)를 그대로 가져와,
결함 사진 창에서 [번호 스탬프 카메라](https://github.com/yeop9701/stamp-camera)로 바로 찍을 수 있게 한 **별도 저장소**다.
원래 저장소는 건드리지 않았다.

- 사용 : <https://yeop9701.github.io/defect-marker-stampcam/> (크롬 메뉴 → 앱 설치. 이름 「결함마킹+스탬프」)
- 번호 스탬프 카메라 : <https://yeop9701.github.io/stamp-camera/> (v1.9.0 이상)

## 쓰는 법

결함 카드의 📷(사진 첨부) → 사진 창 아래 줄

| 단추 | 하는 일 |
|---|---|
| **스탬프 촬영 · 다음 0012** | 앱 안에서 카메라가 열린다. 찍을 때마다 ① 스탬프 카메라 설정대로 번호(+메모·날짜)를 찍어 저장(다운로드 폴더 / 스탬프 카메라 목록, 파일이름 규칙도 같음) ② 이 결함에 사진을 붙이고 ③ **사진번호 칸이 비어 있으면 그 번호를 넣는다** ④ 번호를 하나 올린다. 닫기 전까지 여러 장 이어서 찍을 수 있다 |
| **기본 카메라 + 번호** | 폰 기본 카메라 앱으로 찍고(화질·초점이 더 나은 기기용), 받은 사진에 번호를 찍어 같은 방식으로 붙인다 |

- 촬영 화면 : 다음 번호 · 메모 칸(+「결함 정보로」 = 층수·위치·부재 또는 부재·결함) · 플래시(끔/촬영 때만/계속) · 눌러서 초점 ·
  찍은 장수. Space·Enter·볼륨 단추로도 찍힌다. 가로 화면이면 셔터가 오른쪽.
- **↶ 방금 것 취소** : 방금 찍은 사진을 결함에서 빼고, 스탬프 카메라 목록에서 지우고, 번호를 되돌린다. 그 사진이 사진번호 칸을 채웠으면
  다시 비운다. 여러 번 누르면 차례로 거슬러 간다(촬영 화면을 닫기 전까지). 그 사이 스탬프 카메라 앱 등이 번호를 올렸으면 번호는
  그대로 둔다(겹치지 않게). 다운로드 폴더에 이미 저장된 파일은 브라우저가 지울 수 없어 직접 지워야 한다.
- **촬영 목록** : 셔터 옆 작은 사진을 누르면 스탬프 카메라 목록과 같은 화면이 열린다 — 누르면 크게 보기(다운로드·공유·삭제),
  길게 누르거나 [선택] → 여러 장 다운로드·ZIP·공유·삭제, 전체 ZIP·목록 CSV·전체 삭제. 이번 촬영 화면에서 찍어 결함에 붙인 사진에는
  「결함」 표시가 있고, 지우면 결함에서도 빠진다(그 사진이 채운 사진번호 칸도 비움). 목록에서 지워도 번호는 되돌리지 않는다(스탬프 카메라와 같음).
  목록은 스탬프 카메라 앱과 하나라 여기서 지우면 그쪽에서도 지워진다. 「갤러리 추가」는 결함마킹의 「기본 카메라 + 번호」가 대신한다.
- **다운로드 폴더의 파일은 앱이 지울 수 없다**(브라우저가 막는다). 촬영 목록의 「찍을 때 다운로드 폴더에도 저장」을 끄면
  (= 스탬프 카메라 저장 방식 「앱 목록에만」) 사진이 목록에만 저장되어, 취소·삭제하면 완전히 지워진다. 다 찍은 뒤 ZIP·다운로드로 꺼낸다.
- **점검 앱용 파일이름** : 스탬프 카메라 설정 › 저장 › 파일명 「점검 앱용 : 카메라명+번호 (KIM0012)」 + 카메라명.
  외관조사·3종 체크리스트 앱이 찾는 이름(카메라명 + 번호 4자리)으로 저장되어, 다운로드 폴더를 그대로 그 앱들의 사진 폴더로 쓸 수 있다.
  결함마킹의 사진번호 칸(16)과 외관조사 앱의 「사진번호 16 + 카메라 k」가 같은 파일(KIM0016.jpg)을 가리킨다.
- 사진번호 칸에 이미 값이 있으면 그대로 둔다(두 번째 장부터도 그대로). 사진번호를 넣은 것은 실행취소(Ctrl+Z)로 되돌릴 수 있다.
- 기존의 「앨범에서 선택」「촬영」「사진 촬영」은 그대로 있다(번호를 찍지 않는 예전 방식).

## 번호가 이어지는 원리

두 앱이 같은 주소(`yeop9701.github.io`) 아래에 있으면 브라우저가 저장 공간을 같이 쓴다.

- 번호·메모·저장 방식 = 스탬프 카메라 설정 `localStorage['stampcam.settings.v1']` — 찍을 때마다 새로 읽고, 올린 번호를 곧바로 써 둔다
- 촬영 목록 = 스탬프 카메라 IndexedDB `stampcam / shots` — 결함마킹에서 찍은 사진도 스탬프 카메라 목록·ZIP 에 나온다
- 스탬프 카메라 **v1.8.0** 부터는 다시 볼 때(또는 다른 탭에서 바뀌는 즉시) 번호·메모를 새로 읽는다. 그 전 판은 뒤에 떠 있다가
  옛 번호로 찍어 번호가 겹칠 수 있다

그래서 **파일로 열거나(file://) 다른 주소에 올리면** 번호는 그 주소 안에서만 이어진다(동작 자체는 된다).

스탬프 카메라 설정의 저장 방식이 「공유」면, 찍을 때마다 공유 창이 떠서 결함 기록이 끊기므로 스탬프 카메라 목록에만 저장한다.

## 파일

```
stampcam/src/*.js     번호 스탬프 카메라 js/ 그대로 복사 (camera·stamp·counter·settings·storage·save, v1.9.0)
stampcam/bridge.js    연결 코드 (촬영 화면, 스탬프 → 저장 → 번호 올리기, window.StampCam)
stampcam/build.mjs    위 둘을 한 파일로 묶는다  →  node stampcam/build.mjs
stampcam/stampcam.js  묶인 결과 (index.html 이 <script src> 로 읽는다. 직접 고치지 않는다)
index.html            사진 창에 단추 두 개 + 「번호 스탬프 카메라 연결」 절 (photoTagKey · attachStampShot)
tests/test-stampcam.mjs  연동 검사 90항목
```

결함마킹 앱은 모듈이 아닌 일반 스크립트로 돌고 파일로도 열리므로 ES 모듈 import 를 쓰지 않고 한 파일로 묶었다.
스탬프 카메라 코드를 고치면 `stampcam/src/` 에 다시 복사하고 `node stampcam/build.mjs`.

원본과 바꾼 곳 (위 연동 말고) :

| | 원본 defect-location-marker | 여기 |
|---|---|---|
| 서비스워커 | 캐시 우선 · 옛 캐시를 **이름과 상관없이 모두** 지움 | 네트워크 우선(브라우저 캐시 건너뜀) · **이 앱 캐시만** 지움 — 원본 방식은 같은 주소의 스탬프 카메라 오프라인 캐시까지 지운다 |
| 앱 이름 | 결함마킹 | 결함마킹+스탬프 (두 앱을 같이 설치해도 구분되게) |

       --use-fake-device-for-media-stream --use-fake-ui-for-media-stream about:blank

타고, 다운로드된 파일이름, 스탬프 카메라 목록, 스탬프 카메라 앱의 다음 번호, 떠 있는 스탬프 카메라가 바뀐 번호를 따라가는지까지 본다.
